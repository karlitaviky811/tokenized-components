lib-shared-table

Shared Table

Tabla configurable con columnas dinámicas, paginación, templates custom para celdas y soporte de row click. Incluye cuatro patrones de integración con modales.

Layout y altura

El componente tiene dos modos de altura, seleccionados según el contexto del padre.

Modo stretch (default)

Sin pasar height, la tabla usa flex: 1 1 0 para ocupar todo el espacio disponible del padre. El padre debe ser un flex column con altura definida. 

// SCSS del padre
.mi-pagina {
  display: flex;
  flex-direction: column;
  height: 100dvh;   // o 100%, o un valor fijo
  padding: 1rem;
  gap: 1rem;
}
<!-- la tabla ocupa todo lo que queda bajo el encabezado -->
<div class="mi-pagina">
  <h1>Título</h1>
  <lib-shared-table [columns]="cols" [data]="rows" />
</div>

Modo altura fija

Cuando el padre es un flujo de documento normal (sin flex/grid), pasá height directamente. La tabla se autogestiona sin necesitar CSS externo. 

<lib-shared-table
  [height]="'400px'"
  [columns]="cols"
  [data]="rows"
/>
<!-- altura mínima y máxima -->
<lib-shared-table
  [minHeight]="'200px'"
  [maxHeight]="'600px'"
  [columns]="cols"
  [data]="rows"
/>

SharedTableColumn

interface SharedTableColumn<T> {
  key: string;         // propiedad del objeto o ID de columna
  header: string;      // texto del encabezado
  align?: 'start' | 'center' | 'end';
  width?: string;      // ej: '120px', '20%'
  cell?: (row: T, index: number) => unknown;
}

El tipo de fila DEBE llevar index signature, porque SharedTableColumn<T> restringe T extends Record<string, unknown>.

type DemoUser = {
  id: string;
  name: string;
  [key: string]: unknown;   // obligatorio
};

Integración con modales

Cuatro patrones reales de combinación tabla + modal. Todos usan los stores de la librería (ConfirmModalStore, SideModalStore), no Dialog directo.

1. Row click → confirmación

El caso más común: la fila es clickeable y abre una confirmación antes de navegar o cargar el detalle. Requiere enableRowClick junto a rowClick; sin el input, el output nunca emite.

❖ Row click → ConfirmModal </>
Building Blocks

Uso

private readonly confirmModal = inject(ConfirmModalStore);

onRowClickConfirm(row: DemoUser): void {
  this.confirmModal
    .openWithDescription(
      'Abrir ficha de ' + row.name,
      'Rol ' + row.role,
      'Abrir',
      'Cancelar',
    )
    .closed.subscribe((confirmed) => {
      if (confirmed) { /* navegar al detalle */ }
    });
}
<shared-table
  [columns]="columns"
  [data]="data"
  [enableRowClick]="true"
  (rowClick)="onRowClickConfirm($event)"
/>

2. Acción por fila → confirmación destructiva

Columna de acciones con cellTemplate. La confirmación se resuelve por closed y solo entonces se muta el estado. Nota: lib-icon-button no expone output propio, se escucha (click).

❖ Eliminar fila → ConfirmModal </>

Building Blocks

Uso

onDeleteRow(row: DemoUser): void {
  this.confirmModal
    .openWithIcon(
      '¿Eliminar a ' + row.name + '?',
      'Esta acción no se puede deshacer.',
      'Eliminar',
      'Cancelar',
      'delete',
    )
    .closed.subscribe((confirmed) => {
      if (!confirmed) return;
      this.users.update((list) => list.filter((u) => u.id !== row.id));
    });
}
<shared-table [columns]="deletableColumns" [data]="users()">
  <ng-template cellTemplate="actions" let-row>
    <lib-icon-button (click)="onDeleteRow(row)">
      <span class="material-symbols-outlined">delete</span>
    </lib-icon-button>
  </ng-template>
</shared-table>

3. Selección múltiple → confirmación con lista

Checkbox por fila vía cellTemplate. Las filas seleccionadas se mapean a ConfirmModalListItem[] y se pasan a openWithScrollableList, para que el usuario revise el lote antes de confirmar.

❖ Selección → ConfirmModal con lista </>
Building Blocks

Uso

confirmSelection(): void {
  const listItems: ConfirmModalListItem[] = this.selectedRows().map((u) => ({
    id: u.id,
    label: u.name,
    supportingText: u.email,
    amount: u.amount,
  }));

  this.confirmModal
    .openWithScrollableList(
      'Confirmar desembolso',
      'Se procesarán ' + listItems.length + ' registros.',
      listItems,
      'Procesar',
      'Cancelar',
    )
    .closed.subscribe((confirmed) => {
      if (confirmed) this.selectedIds.set([]);
    });
}
<ng-template cellTemplate="select" let-row>
  <lib-checkbox
    [checked]="isSelected(row)"
    (checkedChange)="toggleSelection(row, $event)"
  />
</ng-template>

4. Row click → panel lateral de detalle

Cuando el detalle es extenso, un panel lateral evita perder el contexto de la tabla. Ojo con esta restricción: openSideModal proyecta el contenido con NgComponentOutlet, que NO acepta inputs. El dato de la fila se comparte por un store inyectable.

❖ Row click → SideModal </>
Building Blocks

Uso

Store compartido, porque el panel no puede recibir inputs:

@Injectable({ providedIn: 'root' })
export class SelectedUserStore {
  private readonly _user = signal<DemoUser | null>(null);
  readonly user = this._user.asReadonly();
  select(user: DemoUser | null): void { this._user.set(user); }
}

La tabla escribe la fila y abre el panel:

private readonly sideModal = inject(SideModalStore);
private readonly selectedUser = inject(SelectedUserStore);

onRowClickPanel(row: DemoUser): void {
  this.selectedUser.select(row);
  this.sideModal.openSideModal(UserDetailPanel, 'Detalle · ' + row.name, '22rem');
}

El panel lo lee por inyección:

export class UserDetailPanel {
  protected readonly user = inject(SelectedUserStore).user;
}
